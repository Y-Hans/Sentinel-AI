### 2.2 Pipeline Completeness Determination

> **Critical Finding**: The four `.pkl` files alone **DO NOT** constitute a complete Python inference pipeline.

The model classifier (`champion_v2_model.pkl`) and scaler (`champion_v2_scaler.pkl`) strictly require **2,070 input dimensions**. The two TF-IDF vectorizers only produce $1,500 + 500 = 2,000$ features. The remaining **70 features** are handcrafted, deterministic domain signals generated by Python code in `Messages-ml/scripts/feature_extraction.py`, `text_normalization.py`, `sender_parser.py`, and `feature_config.py`.

### 2.3 Exact Preprocessing & Feature Extraction Flow

The exact inference pipeline follows this ordered sequence:

```
Verbatim SMS Raw Text + Sender Header
  ↓
1. Text Normalization (text_normalization.py)
   - Zero-width character removal (\u200b, \u200c, \ufeff, etc.)
   - NFKD Unicode normalization
   - Cyrillic/Greek homoglyph replacement (e.g. Cyrillic 'а' -> Latin 'a')
   - Whitespace collapsing & lowercase conversion
  ↓
2. Sender Header Parsing (sender_parser.py)
   - DLT entity code regex matching (e.g., "VK-AMAZON" -> "AMAZON", category="DELIVERY")
   - Phone number regex, shortcode regex, and alphanumeric header categorization
  ↓
3. Deterministic Feature Extraction (70 float features)
   - Structural metrics (14 features: length, uppercase ratio, digit ratio, punctuation, mixed script)
   - Urgency & Pressure signals (4 features: "immediately", "deadline", "hours left")
   - Fear, Penalty & Threat terms (7 features: "blocked", "suspended", "police", "electricity cut", "KYC")
   - Authentication signals (5 features: "OTP", "PIN", "password", numeric codes)
   - OTP Intent classification (5 features: warning vs disclosure request vs delivery context)
   - Financial & Transactional terms (6 features: debit/credit, currency amounts, masked accounts)
   - Call-to-Action / Routing (7 features: URLs, URL shorteners, raw IP links, .apk links, phone numbers, UPI VPAs, WhatsApp links)
   - Sender Header Cross-Consistency (6 features: phone sending banking alerts, DLT valid header)
   - Legitimate Institutional Context (5 features: "income tax", "uidai", "official portal")
   - Interaction Features (11 features: urgency * legit_intent, fear * CTA, etc.)
  ↓
4. Word TF-IDF Vectorization (1,500 float features)
   - N-gram range: `(1, 2)` (unigrams and bigrams)
   - Stop words: `"english"`
   - Sublinear TF: `False` | Smooth IDF: `True` | Norm: `L2`
   - Token pattern: `(?u)\b\w\w+\b` | Max features: 1,500
  ↓
5. Character TF-IDF Vectorization (500 float features)
   - Analyzer: `"char_wb"` (character n-grams within word boundaries)
   - N-gram range: `(3, 5)`
   - Sublinear TF: `False` | Smooth IDF: `True` | Norm: `L2`
   - Max features: 500
  ↓
6. Vector Concatenation
   - Exact concatenation order: `np.hstack([xd (70), xw (1500), xc (500)])` → Shape: `(1, 2070)`
  ↓
7. StandardScaler Standardization
   - Applied element-wise: $z_i = \frac{x_i - \mu_i}{\sigma_i}$ for all $i \in [0, 2069]$
   - Scaler parameters: $\mu$ (2,070 floats), $\sigma$ (2,070 floats)
  ↓
8. Classifier Inference
   - Type: `HistGradientBoostingClassifier`
   - Hyperparameters: `max_iter=300` (converged at 103 iterations), `learning_rate=0.1`, `max_depth=7`, `max_leaf_nodes=31`, `min_samples_leaf=20`, `l2_regularization=0.0`, `random_state=22`
   - Output: 3-class probability distribution $[P(\text{BENIGN}), P(\text{SUSPICIOUS\_SPAM}), P(\text{MALICIOUS})]$ via 309 trees (3 trees/iteration $\times$ 103 iterations)
  ↓
9. Threshold & Decision Logic
   - Operating threshold: $\tau = 0.704$
   - Adjudication rule:
     ```python
     P_non_benign = P(SUSPICIOUS_SPAM) + P(MALICIOUS)
     if P_non_benign >= 0.704:
         if P(SUSPICIOUS_SPAM) > P(MALICIOUS):
             return SUSPICIOUS_SPAM  # Class 1
         else:
             return MALICIOUS        # Class 2
     else:
         return BENIGN               # Class 0
     ```
```

### 2.4 Scaler Necessity for Messages-ML

* **Can we delete `champion_v2_scaler.pkl`?**: **`NO`**.
* **Rationale**: The underlying `HistGradientBoostingClassifier` was trained on scaled features ($z$-scores). Because standard scaling alters feature magnitudes (especially between dense TF-IDF sparse outputs and large discrete character counts), omitting the scaler destroys classification accuracy and leads to catastrophic false positives/negatives.
* **Android Representation**: The 2,070 means and 2,070 scales must be exported to a lightweight flat JSON or binary float array (`FloatArray(2070)`) and applied prior to tree/model evaluation.

### 2.5 Credential Theft Recall Nuance

In accordance with project guidance, Messages-ML Champion V2 achieves **79.19%** (1,823/2,302) recall against the raw historical uncurated dataset labels. Forensic analysis reveals:
* **Verified Malicious Credential Attacks**: **15 / 15 (100.00% Recall)**.
* **Conservative Suspicious Stratum**: **605 / 656 (92.23% Recall)**.
* The remaining uncalled samples are ambiguous administrative notices or non-phishing bulk templates.

### 3.3 Scaler Determination for URL-ML

* **Can we delete `URL-ml/model/scaler.pkl` and `URL-ml/model/scaler.json`?**: **`YES`**.
* **Empirical Evidence**: V7 uses `HistGradientBoostingClassifier(max_iter=350, learning_rate=0.06, l2_regularization=5.0)`. Decision tree algorithms and histogram gradient boosters evaluate quantile threshold splits directly on raw feature values; they do not perform distance calculations and are completely invariant to monotonic feature scaling.
* The files `scaler.pkl` and `scaler.json` in `URL-ml/model/` are 15-feature artifacts from the obsolete V1 neural baseline and are 100% unused by V7.

### 3.4 Safe-Domain Gated Adjudication Logic

To eliminate false positives on legitimate complex URLs (such as `trello.com/login`, `github.com/torvalds/linux/pull/123`), V7 wraps the raw model output in a deterministic gating rule:

1. **Threat Trigger Check**: `has_threat = True` if any threat indicator is active:
   * Brand impersonation $> 0$, Suspicious TLD $> 0$, IP host $> 0$, Suspicious extension $> 0$
   * Open redirect $> 0$, Path suspicious words $> 0$, Query suspicious words $> 0$
   * Double encoding $> 0$, `@` symbol $> 0$, Punycode $> 0$, Unusual port $> 0$
   * Consecutive slashes $> 0$, Non-ASCII $> 0$, Nested URL $> 0$, Subdomains $\ge 2$
2. **Safe Brand Verification**: `is_safe_brand = (Safe_Brand_Domain == 1.0) and (not has_threat)`
3. **Adjudication**:
   $$\text{If } \text{is\_safe\_brand} \text{ and } P_{\text{raw}} < 0.80 \implies P_{\text{final}} = 0.001$$
4. **Decision**: $\text{MALICIOUS}$ if $P_{\text{final}} \ge 0.225887$, else $\text{BENIGN}$.

## 6. Part 5 — Python → Kotlin Equivalence Requirements

### 6.1 URL-ML Quantile Binning Equivalence

In Python scikit-learn, `HistGradientBoostingClassifier` maps continuous float values to histogram bins during `_bin_mapper.transform()`. 

> **Crucial Implementation Rule**: In Kotlin, the bin mapping **MUST** use left-sided binary search:
> $$\text{bin\_idx} = \text{binarySearch}(\text{thresholds}, \text{val}, \text{side} = \text{'left'})$$

If `side = 'right'` is used, boundary values (such as feature values of exact `0.0`) are placed into bin 1 instead of bin 0, causing small margin discrepancies. When `side = 'left'` is used, numerical parity with scikit-learn is **exact ($1.39 \times 10^{-17}$ max difference)** across thousands of test URLs.

### 6.2 Messages-ML Hash & Tokenization Equivalence

* **MurmurHash3 (32-bit x86)**: The deterministic character n-gram hasher in `feature_extraction.py` uses the standard MurmurHash3 algorithm with seed `42`. This is bit-for-bit identical to standard JVM implementations (e.g. Google Guava `Hashing.murmur3_32_fixed(42)`).
* **Regex Word Tokenizer**: Scikit-learn's `(?u)\b\w\w+\b` must be implemented using Java/Kotlin `Pattern.compile("\\b\\w\\w+\\b", Pattern.UNICODE_CHARACTER_CLASS)`.
* **Cyrillic/Greek Homoglyphs**: The exact 21-character mapping table in `text_normalization.py` must be mirrored in Kotlin to neutralize homoglyph evasion attacks.
